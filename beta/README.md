# AirPods 小助手 控制实验室 · 1.10.0-beta.2

这是 Windows x64 **独立的控制功能实验包**，不是正式版替换包。版本字段在 `AirPodsBuddy.Beta/AirPodsBuddy.Beta.csproj`。当前主应用本机候选 1.9.38、公开正式版 1.9.24。本包尚未公开发布。

## 已实现的代码

- AAP 入耳状态订阅与展示：入耳 / 未入耳 / 在盒内，主副耳不冒充左右耳。首版仅观察，**不自动暂停或恢复媒体**。
- 关闭 / 降噪 / 通透命令；自适应为 H2 可选实验。需先收到设备模式上报、选定支持的策略型号，再开放按钮。
- 每次模式写入等待最多 4 秒的新模式上报；匹配、回读不一致、超时、中断分别显示。写成功不是切换成功，新上报也不能证明因果。超时后关闭控制会话，防止旧回包用于下一次命令。
- 型号按设备及父节点名称推测；未知保留未知。可以手动指定 Pro / Pro 2 / Pro 3 / AirPods 4 ANC / Max。手动设置按设备接口的本地哈希保存。**名称推测不是读取硬件型号，也不是功能认证**。
- 只在用户明确打开时连接选定的控制接口；多目标不自动选第一个。退出或故障取消读取并释放句柄；不自动重连、重试或恢复模式。

## 运行

1. 本机独立实验包可自包含发布；framework-dependent 开发构建需微软 .NET Desktop Runtime 8 x64。
2. 解压全部文件，运行 `AirPodsBuddy.Beta.exe`。先通过 Windows 连接耳机，再点“检测控制通道”。
3. 本轮只接入了**已有 MagicAAP 兼容驱动接口**；不附带驱动，不安装驱动，不改变系统保护配置。无接口时会明确显示前置条件未满足，这不等于耳机不支持。
4. 明确选中目标后选择型号并打开控制通道。普通模式先不勾 H2 实验能力；自适应需明确勾选并重新打开会话。
5. 戴上、摘下、放回盒内，观察设备上报。若没有初始模式报告，可用耳柄切换一次模式观察；未收到报告时软件按钮保持不可用。
6. 点模式按钮，核对新回读并实听。回读超时或不一致都不能写成验证通过。

避免与 MagicPods 等其他控制客户端同时打开同一控制通道。独立包不改正式版目录、不自启、不访问麦克风、不建立播放流、不切音频路由、不改配对、不重置蓝牙。它**不是 HFP 通话音质修复版**。

## 当前验收状态

本次离线协议 / 会话检查 3115 项通过，独立本机安装、自包含 EXE、UI smoke 见脱敏 doc/13。历史证据不当作当前结果。本机只读 probe 发现 **0 个兼容接口**；没有打开硬件通道。**Pro 3 的入耳上报、降噪 / 通透实听、自适应与驱动兼容均未真机验收**。底层公开协议样本来自 Pro 2，不能据此承诺 Pro 3 兼容。当前不是面向全部粉丝的硬件验证完成版。

## 开发与回退

```powershell
& 'C:\Program Files\dotnet\dotnet.exe' run --project beta/tests -c Release
& 'C:\Program Files\dotnet\dotnet.exe' build beta/AirPodsBuddy.Beta -c Release
# 无 UI 的只读探测，报告不含名称、地址、序列号或原始报文：
.\AirPodsBuddy.Beta.exe --probe C:\Temp\aap-probe.json
```

Beta 的独立配置为 `%LOCALAPPDATA%\AirPodsBuddyBeta\models.json`，只在手动更改型号时写入；持久化不保存原始设备路径或名称。退出实验包即停止控制，不需要替换回正式版。手动切过的耳机模式不会自动反向更改，按耳柄或原设备自行选择所需模式。源文件级副本回退见验证目录的 `ROLLBACK.sh`，不对运行中的用户安装目录操作。

完整协议来源、兼容接口考证、已知限制、真机矩阵与下一步见 `../doc/13-AAP实验版.md`。
