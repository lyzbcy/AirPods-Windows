# 02 · 架构与原理（每个模块怎么工作）

> 读这份文档的时机：**改代码之前**。这里逐模块讲清原理，避免重复踩坑。

## 0. 总体结构

```
airpods_buddy.ahk (AHK v2 宿主，约450行)
 ├─ WebView2 窗口 ←─────── JS 桥(双向) ───────→ webui/index.html (前端)
 │   (lib/WebView2/WebView2.ahk, thqby 库)      └─ index_built.html(构建产物,资源内联)
 ├─ 蓝牙核心 (Bthprops.cpl DllCall) ←── 复用上游 ChromuSx 逻辑
 ├─ 日志系统 (logs/app-YYYY-MM-DD.log)
 └─ 自动更新 (GitHub Releases)
编译产物: dist/AirPodsBuddy.exe = AHK解释器 + 脚本 + 内嵌HTML/DLL
```

## 1. 主程序 airpods_buddy.ahk（按执行顺序）

1. **`Persistent`**：常驻托盘的关键。没有它，关窗=程序退出（v1.2.0 踩过的坑）
2. **日志系统**（见 §5）
3. **资源定位**：未编译时直接用源码目录；`A_IsCompiled` 时从 exe 里
   `FileInstall` 释放 `index_built.html` + `WebView2Loader.dll` 到 `%TEMP%\AirPodsBuddy_app`
4. **无边框窗口**：`Gui("-Caption")` + DwmSetWindowAttribute(33) 圆角，468×748 逻辑像素
5. **WebView2 创建**（3 次重试，防安全软件瞬时拦截），用户数据目录
   `%LOCALAPPDATA%\AirPodsBuddy_webview`
6. **`NavigateToString(整个HTML字符串)`** 加载前端
7. **`myGui.Show()` 后必须 `SyncWebView()`**（见 §2 白屏原理）
8. 托盘菜单 / 3 秒后异步检查更新

## 2. WebView2 承载（白屏问题的原理！）

**关键事实**：控制器在**隐藏窗口**上创建时，`Controller.IsVisible` 初始为
`false`，WebView2 会**挂起渲染**——此时页面 JS 照常运行（rpc、轮询都正常），
但屏幕永远是白的。这就是 v1.1.x"白屏但日志全绿"的根因。

因此 `SyncWebView()` 在每次窗口显示/尺寸变化后执行：
```ahk
wvc.Fill()          ; 边界 = 客户区（隐窗创建时边界也是错的，必须重填）
wvc.IsVisible := true
```
绑定在 `Gui.OnEvent("Size", SyncWebView)` + Show 之后手动调用一次。

其他要点：
- DPI 150% 环境：`innerWidth` 上报 468（CSS 像素），GetClientRect 是 702（物理像素），均正常
- `PrintWindow` 抓 WebView2 的 GPU 合成内容**不可靠**（常抓出全白图），
  验证渲染要用"页面探针"（ExecuteScriptAsync 查询 DOM）或置前截图
- WebView2 库：`lib/WebView2/WebView2.ahk`（thqby v2.0.4，对应 Loader 1.0.2903.40）

## 3. JS 桥协议（AHK ⇄ 前端）

**前端 → AHK**：`chrome.webview.postMessage("cmd\x1Fid\x1Farg")`
（`\x1F`=单元分隔符）。AHK 侧 `WebMessageHandler` 按首段分发表。

**AHK → 前端**：`ExecuteScriptAsync('window.__rpc(id, <payload>)')`。
**payload 必须是合法 JS 字面量**——这是 v1.2.0 修的第三个 bug：
- 已是字面量的直接用：`true` / `null` / `JsonStr("文本")`（带引号）
- **JSON 数组必须再包一层**：`Reply(id, JsonStr(BuildDevicesJson()))`，
  否则前端拿到的是已解析对象，`JSON.parse(对象)` 抛 `"[object Object]"`
  异常、设备列表永远渲染不出来

**JS 错误回传**：前端 `window.onerror`/`unhandledrejection` → `jserror`
命令 → 写入日志 `[JS-ERROR]`。调试前端问题不用开 DevTools（已禁用）。

**轮询**：前端每 4 秒 `statuspoll`（不写日志防刷屏），设备状态变化时重渲染。

**窗口拖动**：WebView2 里的 HTML 无法直接拖动无边框宿主窗口。前端在
顶栏/标题区 `mousedown`（左键且不在按钮上）→ `rpc('windrag')` → AHK
`PostMessage(WM_NCLBUTTONDOWN, HTCAPTION)` 给主窗口 → 进入系统原生
拖动循环。

## 3.5 设备优先级（v1.3.0）

- 持久化：`<exe目录>\device_priority.txt`，每行一个设备名（UTF-8）
- 排序键：用户优先序号（未设置=999）→ Apple 家族（名字含 airpods/beats）
  优先 → 名称字典序
- "一键连接"（托盘 & 界面大圆钮）= 连接排序后**第一个未连接**的设备；
  "一键断开" = 断开**全部**已连接设备
- 前端 ▲▼ 按钮 → 本地交换顺序 → `setprio`（SEP 连接的名字串）→ 保存+重排
- 局限：按名字识别 Apple 设备，改过名的 AirPods（如"捞鱼不知道喔"）
  会被归入"其他"——用户手动置顶即可

## 4. 蓝牙核心（复用上游，原理备忘）

- 设备枚举：`Bthprops.cpl\BluetoothFindFirstDevice/FindNextDevice`，
  `BLUETOOTH_DEVICE_INFO` 结构 560 字节，名字在偏移 +64（UTF-16）
- 音频设备过滤：Class of Device `(cod >> 8) & 0x1F == 4`（Audio/Video 大类）
- 已连接判断：结构偏移 +20 的 `fConnected`
- 连接/断开 = 开/关两个服务：
  - HFP（麦克风）`{0000111e-...}`，A2DP（立体声）`{0000110b-...}`
- `BluetoothSetServiceState` 状态机（hr 返回值）：
  `0`=成功；`87/0x80070057`=参数错（断开时视为已断）；`1060`=服务不存在；
  `1168`=HFP 断开时视为 absent；其余重试，上限 `maxRetries=10`
- 删除配对：`BluetoothRemoveDevice`（地址在结构偏移 +8，uint64）
- **权限**：普通用户权限即可，但蓝牙开关状态会影响结果

## 5. 日志系统（v1.2.0 新增）

```
位置: <exe目录>\logs\app-YYYY-MM-DD.log   （部署机 = %LOCALAPPDATA%\BluetoothDeviceConnector\logs）
格式: [2026-08-19 00:26:18] [INFO] 消息     级别: INFO/WARN/ERROR
自动清理: 启动时删除 7 天前的日志（CleanOldLogs，注意 AHK v2 用 DateAdd 不用 EnvSub!）
```
设计原则（血泪教训）：
- **日志写入永不抛错**：UTF-8 → CP0 → `OutputDebugString` 三级回退
- **全局 `OnError` 拦截**：任何未捕获错误写日志并静默结束线程，
  **绝不弹 AHK 错误对话框到用户脸上**
- `statuspoll` 不记录（4 秒一条会刷屏）；其他 rpc 全记录

## 6. 自动更新

检查 `api.github.com/repos/lyzbcy/BluetoothDeviceConnector/releases/latest` →
版本比较 → 下载 `AirPodsBuddy-Windows.zip` → `tar -xf` 解压 → 复制为
`_new.exe` → 生成 swapper.ps1（等旧进程退出→替换→重启）→ 自杀 1.2 秒后。
**发新版前必须**：更新 `APP_VERSION`、打 tag、传 zip（zip 内含 exe+说明）。

## 7. 编译与部署（完整流程）

```powershell
# 1. 改前端后重建（把 webui/assets 图片内联为 base64）
powershell -File webui\build_ui.ps1          # 产出 webui/index_built.html

# 2. 编译（工具链已下载到 tools/ahk2exe_stable/，见 05 的坑#2）
#    必须用 Start-Process 分离启动 Ahk2Exe，直接 bash 调用会静默失败!
#    脚本必须在仓库根目录（#Include/FileInstall 相对路径）
$proc = Start-Process tools\ahk2exe_stable\Ahk2Exe.exe -ArgumentList `
  '/silent','/compress 0','/in airpods_buddy.ahk','/out dist\AirPodsBuddy.exe',`
  '/base "C:\Users\24676\AppData\Local\Programs\AutoHotkey\v2\AutoHotkey64.exe" `
  -Wait -PassThru -WorkingDirectory E:\github\BluetoothDeviceConnector
# exit=0 即成功（ nonzero = 失败，且错误信息经常为空，见 05 坑#3）

# 3. 部署：杀旧进程 → 复制到 %LOCALAPPDATA%\BluetoothDeviceConnector\
#    （原 deploy.ps1 已被安全软件吃掉，步骤见 04 待办）
```
桌面/开机快捷方式指向 `%LOCALAPPDATA%\BluetoothDeviceConnector\AirPodsBuddy.exe`。
