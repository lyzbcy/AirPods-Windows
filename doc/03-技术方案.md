# 03 · 技术方案

> 读这份文档的时机：做技术决策、升级依赖、或想知道"为什么这么选"。

## 技术栈与版本（本机实测锁定）

| 组件 | 版本 | 位置/来源 |
|---|---|---|
| AutoHotkey v2 | 2.0.26 (x64) | `%LOCALAPPDATA%\Programs\AutoHotkey\v2\` |
| WebView2 AHK 库 | thqby v2.0.4 | `lib/WebView2/WebView2.ahk`（含 Promise.ahk） |
| WebView2Loader.dll | 1.0.2903.40 | `lib/WebView2/64bit/`（编译时内嵌） |
| Ahk2Exe 编译器 | 1.1.36.02f（稳定版） | `tools/ahk2exe_stable/`（GitHub Releases 下载；**1.1.37 alpha 有问题**） |
| WebView2 运行时 | Evergreen（系统自带/Edge 同源） | 用户数据目录 `%LOCALAPPDATA%\AirPodsBuddy_webview` |

## 为什么 AHK v2 + WebView2

| 方案 | 体积 | 依赖 | UI 上限 | 结论 |
|---|---|---|---|---|
| **AHK+WebView2 ✅** | 2.4MB | 无（系统自带 Edge） | 现代 HTML/CSS | 选它 |
| 纯 AHK Gui | 2.4MB | 无 | 原生控件，米白风难做 | 表现力不足 |
| C# WinForms/WPF | 5-10MB | .NET 运行时 | 高 | 开发重 |
| Electron/Tauri | 80MB+/8MB | WebView2/自带 | 最高 | 杀鸡用牛刀 |

## 前端构建链

`webui/index.html`（源码，引用 `assets/` 相对路径图片）
→ `webui/build_ui.ps1`（把 7 张图片转 base64 data URI 内联）
→ `webui/index_built.html`（~894KB）
→ `FileInstall` 内嵌进 exe → 运行时释放到 `%TEMP%\AirPodsBuddy_app\`
→ `NavigateToString()` 整串加载。

**约束**：
- `NavigateToString` 内容上限 2MB（当前 894KB 字符 ≈ 1.79MB UTF-16，**接近上限，
  以后别再加大图**；超了就得改用 `SetVirtualHostNameToFolderMapping` 方案）
- 图片改动后必须重跑 build_ui.ps1 再编译，否则 exe 里是旧图

## 关键设计决策记录

| 决策 | 备选 | 理由 |
|---|---|---|
| `NavigateToString` + base64 内联 | 虚拟主机映射本地文件 | 单文件分发优先；代价见上 |
| 全局 OnError 静默 + 日志 | 保持 AHK 默认弹窗 | 用户被"奇怪报错弹脸"吓过，明确要求不弹窗 |
| WebView2 创建重试 3 次 | 单次 | 本机安全软件会瞬时拦截（0x800704C7） |
| 关窗=隐藏到托盘 | 关窗=退出 | 工具型常驻设计；`Persistent` 是关键 |
| 日志按天分文件+7天清理 | 单文件追加 | 便于按日期排查，防无限膨胀 |
| 音频方案 A2DP+HFP 默认 | 纯 A2DP | 麦克风可用优先；上游脚本支持切换 |

## 性能与资源

- 空闲占用：~30MB（AHK）+ WebView2 浏览器进程组（共享 UDF，多实例便宜）
- 启动到界面可见：<2 秒（含 WebView2 环境创建）
- 蓝牙操作：连接 2-8 秒（受系统蓝牙栈影响，重试机制兜底）
