## A. 未解决的问题（未 laojue 的点）

### A1. 本机安全软件间歇性干扰（最大环境风险）
- **现象①**：AHK `FileAppend` 写文件被瞬时拦截，报 `0x800704C7`（操作已取消），
  且时好时坏（同一脚本一分钟前成功一分钟后失败）
- **现象②**：**项目里的 .ps1/.ahk 文件会被悄悄删除/隔离**——`deploy.ps1`、
  `make_shortcuts.ps1`、E 盘一堆测试脚本都消失过
- **建议**：把 `E:\github\BluetoothDeviceConnector` 和
  `%LOCALAPPDATA%\BluetoothDeviceConnector` 加入杀软/Defender 白名单；
  重要脚本提交 git 保存
- 相关搜索结论：[Microsoft Q&A 0x800704C7](https://learn.microsoft.com/en-us/answers/questions/5882193/how-to-fix-error-code-0x800704c7)、[WebView2 环境创建失败案例](https://github.com/MicrosoftEdge/WebView2Feedback/issues/5192)

### A3. NavigateToString 容量逼近上限

### A4. Mac：Beats Solo³ `openConnection` 返回 -536870186
2026-08-19 真机日志：连 '捞鱼的Beats Solo³' 三次全部失败（同一时段
AirPods Pro 秒连成功）。疑似设备关机/不在范围/被 iPhone 占用，待复现
确认。当前表现：左键无反应只有日志——**失败无用户反馈**这个 UX 问题
待解决（注意红线：不许弹窗，考虑图标短暂变化或系统通知）。

### A5. Windows 蓝牙栈卡死（2026-09-21 实锤病例；勿再误诊成代码 bug）
- **病例**：用户机连续 7 次连接（19:19–19:39），`BluetoothSetServiceState`
  全部返回成功（日志无一条 `DoAction connect failed`），但 LinkVerify 的
  fConnected 真实链路位 9s 内从未起来（7 条 `link NOT up`）。
- **排除法**：手机蓝牙开/关、耳机放回盒重开、App 重启——全部无效；
  **重启电脑立即恢复**，且恢复的连接是系统开机自动建的（日志里 App 无
  任何连接动作）→ 卡的是 bthserv/bthport/无线电层，不是本程序。
- **旁证**：系统事件日志 BTHUSB 事件 18「无法在本地适配器存储蓝牙链接
  密钥」**每次开机必现**（廉价 dongle 特征）；事发前系统连续运行 22.5h。
  栈被甚么交互弄卡不可考（App 当时挂机 17h 无操作）。
- **处置**：v1.9.11 起连续 2 次链路失败自动开关一次蓝牙无线电（WinRT
  Radio API，无需管理员）再重连一次；一轮故障只一次，用户动作作废，
  失败降级为指引。**若自救也救不回来，重启电脑仍是终极解**。
- **防误诊**：见到成串 `link NOT up` 而无 `DoAction connect failed`，
  先怀疑栈卡死（开关无线电/重启验证），别急着改连接代码。

## B. AI 开发环境陷阱（给未来调试的 AI）

### B1. AI shell（ZCode sandbox）里直接调 Ahk2Exe 会静默失败
`"Failed to compile: "`（错误信息为空）+ 非 0 退出码。
**必须用 `Start-Process` 分离启动**（脱离 bash 的 stdio/环境继承）。已验证：
同一命令 bash 直调=失败，Start-Process=成功。

### B2. /ErrorStdOut 不可信
无控制台环境（bash 管道/GUI 分离启动）下经常**什么都不输出**，别指望它定位
加载错误。**定位语法错误的可靠方法**：用 Ahk2Exe 编译当判定器（exit=0=语法 OK），
对可疑代码块做二分（在仓库根目录、每次用全新文件名）。

### B3. #Include/FileInstall 的相对路径按脚本所在目录解析
把带 `#Include lib\...` 的脚本放到仓库**外**（如 E:\github 根目录）编译
必失败。测试脚本要么放仓库内，要么改绝对路径。**这个坑制造了大量
假阳性**（以为是代码问题，其实是路径）。

### B4. 验证 WebView2 渲染别用 PrintWindow
对 GPU 合成内容经常抓出**全白假图**。可靠方法：① 置前后全屏截图裁剪；
② `ExecuteScriptAsync` 页面探针（查 `document.body.innerText.length`、
`getComputedStyle` 等）。

### B5. 在用户桌面调试 = 弹窗骚扰用户
测试脚本报错会以 AHK 错误对话框形式**弹在用户脸上**（用户已强烈抗议）。
规矩：能不跑 GUI 就不跑；要跑必须 try 包全部、先杀同类进程、验证用
无焦点方式（PrintWindow/日志/退出码）。
**2026-08-25 补**：函数级测试凡可能触到 `MsgBox`/`Gui` 的路径，先在
测试脚本里定义同名 stub（如 `MsgBox(args*) { return "No" }`，v2 允许
覆盖内置函数）再跑——当天两次实测弹窗都源于没打桩。

### B6. bash 写的 .ps1 里中文会乱码
PowerShell 5.1 把无 BOM 的 ps1 当 ANSI 读，here-string 里的中文 needle
永远匹配不上 UTF-8 目标文件。**ps1 里做字符串匹配只用 ASCII 锚点**。
**更狠的变体（2026-08-19 实际事故）**：ps1 里的中文**路径**也会乱码化，
robocopy 会把文件拷进乱码目录（`E:\鍏变韩\鍒涗瘮\`）而不是真实路径
（`E:\共享\创业\`），且脚本自身验证时列出的是乱码路径、看起来"成功"。
**铁律：涉及中文路径的文件操作一律用 bash 内置命令（mv/cp/ls，MSYS
原生 UTF-16 转换），或 ps1 内用 `[char[]` 字符码拼路径。**

### B7. 分叉历史下"reset + 重放自己的版本"会静默覆盖他人的新成果（2026-08-27 事故）
背景：github.io 仓的另一端（Mac）经 gh API 通道发布了落地页 v2.0→v2.2.0
（可交互模拟应用窗口/宠物动画/专属关于子页，共 ~600 行）。本机本地副本
落后于远端；同步时采用"fetch → reset --hard FETCH_HEAD → 把自己工作区
的版本重新应用上去 → push"，重放的是**自己旧 base 上的整文件**，等于把
远端 v2.x 全部内容顶掉（-602 行 +117 行），且 push 成功、无任何告警。
两天后用户发现"模拟样式被改坏"，首轮还误诊成截图问题。
**铁律：**
1. 多端共写一个仓库时，同步 = `pull --rebase` 让 git 做内容级合并，
   **永远不要整文件重放**；
2. push 前必看 `git diff FETCH_HEAD --stat`（或 `@{u}`），**出现大额
   删除必须能解释每一行**；
3. 静态页有自带版本体系的（PAGE_VER/更新日志），回滚/恢复也要**升版本号**
   并写日志条目，否则缓存里的访客永远刷不回正确版本；
4. "别人做的东西更好"是常态——覆盖前先 `git log --all -- <file>` 看看
   别端有没有更新的提交。

### B8.5. bash heredoc 转义腐蚀 AHK 源码的五种形态（2026-09-20 一次全中）
python heredoc 补丁经 JSON/bash 双层转义后写入源码，当日连中五类：
① `B64Utf16` 被吞首字母成 `64Utf16`（加载期报"函数名不能以数字开头"）；
② `<BEL>pp_settings.ini` 的 `<BEL>` 变 BEL(0x07) —— 设置文件读写自始静默失效
   （求好评计数/冷却从未生效）；③ GatherLogTail 的 `<BEL>pp-` 同类 BEL →
   日志收集永远为空；④ `<VT>1.0` 的 `<VT>` 变竖表制符 → 路径无效；
⑤ `""` 引号双写被还原成裸 `"` → AHK 字符串提前闭合。
**防御：给 AHK/PS 源码打补丁一律用 Write 工具写补丁脚本（raw string）+
字节级断言替换，写完必做「控制字符扫描 + 函数名/路径完整性 grep +
编译 oracle」三连；heredoc 直接写含 `\` 序列的内容 = 必腐蚀。**

### B8.6. 转义实体化的隐藏残留：源码文件被控制字节"毒化"成二进制（2026-09-20 v1.9.10 清扫）
B8.5 修的是 AHK 源码，但**webui/index.html 里同族残留漏网**：JS 正则
`[\x00-\x08\x0b\x0c\x0e-\x1f\x7f]` 的转义序列被写成真实控制字节
（NUL/BS/VT/FF/SO/US/DEL 共 7 个）。浏览器里字符类语义碰巧等价 → 功能
零异常，但 `file` 判文件为 data、**grep 静默无输出**（不报 Binary file
matches 时最坑）、部分编辑器/AI 工具直接拒读——本轮实测先被它骗了一轮
（搜前端 rpc 招式扑空）。已还原为 ASCII 转义文本并重建 built；本文件
里的历史展品字节也换成 `<BEL>`/`<VT>` 可读标记。
**防御：任何"文件功能正常但 grep/工具行为诡异"的源码，先跑一遍控制字节
扫描（`[b for b in data if b<0x20 and b not in (9,10,13)]` + 0x7F），
别急着怀疑自己的搜索词。**
**当场再犯实证（同一小时）**：给本文件补 B8.6 时用了 bash heredoc 传
python 补丁，双反斜杠被传输层折叠、再被 python 解释成真实控制字节——
刚写完的"展品"自己变成了污染源，扫描器当场抓住。B8.5 的防御规矩
（Write 工具 + 字节断言）不是摆设，是唯一可靠路径。

### B8.7. commit/CHANGELOG 声称的功能可能从未存在（2026-09-20 用户抓包）
v1.9.9 两条 commit 写着 "feedback logs chunked via webview no-cors"、
CHANGELOG 1.9.7 写着"三层反馈通道（fetch 主通道…）"，用户实测反馈

### B8.8. 本仓 Ahk2Exe 的三个语法怪癖（2026-09-20 排查 exit=17 挖出）
解释器（AutoHotkey64.exe 直跑）全部正常，仅 **Ahk2Exe 编译预处理**炸，
exit=17 且 /silent 下无任何错误详情（只能当判定器做二分）：
① 双引号串内的 `""` 转义**不支持** → 必须写 `` `" ``；
② 单引号串内的 `''` 转义**不支持**（单引号串本身可用，但不能嵌套
单引号字符）；
③ 单行函数体 `f() { expr }` / `f() {}` **不支持** → 大括号必须换行。
历史代码恰好三种写法都没用过，所以一直没炸。**新代码规则：双引号串
内一律 `` `" `` 转义、单引号串内不出现单引号、函数体大括号必换行；
编译 17 时优先按这三条自查再二分。**

### B8.9. 企微机器人 upload_media 的 PowerShell 铁律（2026-09-20 实测）
PS5.1 HttpClient 上传文件给企微群机器人，44001 "empty media data"
的三个真因（Python urllib 同请求全部正常，纯 .NET 栈差异）：
① `MultipartFormDataContent`/`NameValueHeaderValue` 生成的 boundary
参数**带引号**（`boundary="xxx"`）→ 企微不认，必须手拼 multipart
且 boundary 参数**无引号**；
② `filename="..."` 的**闭合引号不能丢**（丢了同样 44001，且报错
一模一样，极易误诊）；
③ `New-Object ByteArrayContent($bytes)` 的数组参数被 PS 展开成 N 个
参数 → 必须 `(,$bytes)` 逗号包裹。
multipart 头尾的 CRLF 用 `[Environment]::NewLine` 运行时构造最稳
（字面控制符不宜过编码层）。定位方法：httpbin.org/post 回显对比
PS 与 python 的实际请求字节。

### B8. 沙箱内 AHK 解释器静默不执行（2026-09-06）
沙箱令牌下 `AutoHotkey64.exe xxx.ahk` 不报错、不退出、不产生任何文件——
脚本疑似根本没执行（连 FileAppend 冒烟都无输出）。**AHK 代码路径的
运行时验证不能在 AI 沙箱内做**：只做 Ahk2Exe 编译语法验证，运行验证
交给用户点一下，或用 PowerShell/.NET/curl 复刻同等逻辑验证。
同类：WinHttp.WinHttpRequest 在沙箱子进程里挂死不动（.NET/curl 同
端点秒通），意见反馈通道因此从 WinHttp 改为 curl.exe 直连。
**2026-09-20 复测**：沙箱内直接跑 AutoHotkey64.exe 简单脚本已正常
（FileAppend 落盘、读回验证全通，见 v1.9.10 修复验证）——B8 现象非永久，
但复杂 GUI 路径仍建议编译 oracle + 用户侧运行。

## C. AHK v2 语言坑

| 坑 | 正解 |
|---|---|
| `EnvSub`/`EnvAdd` 是 v1 命令 | v2 用 `DateAdd(A_Now, -7, "days")`。**调用不存在的函数=脚本加载失败**（秒退/编译失败，且不报错） |
| 函数名 `Log` | 是内置数学函数，同名覆盖行为诡异 | 直接用 `LogMsg` 这类不冲突名 |
| `try`/`catch` 单语句换行体 | 合法但建议都写 `{}`，减少解析歧义 |
| 隐窗创建 WebView2 | `IsVisible=false` → 白屏（本项目头号坑，见 02§2） |
| Gui 不保持脚本存活 | 常驻托盘必须显式 `Persistent` |
| `Promise.then` 回调参数 | 是**解析后的值**本身，不是 Promise 对象（没有 `.Result`） |
| `FileDelete` 删不存在的文件 | 抛 TargetError；与 `FileAppend` 同 try 块会整块跳过 → **首写永远失败**（v1.9.10 前设置/优先级从未落盘的根因）。正解：`if FileExist(p)` 后各自单独 try |
| **`<`/`>` 对字符串** | v2 关系运算符**只做数值比较**，字符串会抛 "Expected a Number"。用 `StrCompare(a,b) < 0` |
| **v1 的 `Menu,Tray,Click`** | v2 属性名是 `A_TrayMenu.ClickCount`。写 `Click := 1` 不报错——静默创建同名普通属性，真实 ClickCount 仍是 2（双击才触发默认项）。表现：托盘左键单击完全无反应。2026-08-19 v1.8.1 由子 Agent 用 UIA 模拟点击 A/B 实证修复 |
| **跨行 juxtaposition 拼接** | 行尾若是完整语句（如 `out .= f(x)`），下一行 `'...'` **不会续行而是被静默丢弃**！字符串拼接一律写单行，或用括号内逗号续行 |
| **`DllCall` 输出参数传值** | `"ptr*", info := 0` **不报错但指针永不回填**（2026-08-25 实测 hr=0 调用成功、出参始终为空）→ 运行时探针差点在**有**运行时的机器上全量误报缺失、每次开机弹修复窗。必须写 `"ptr*", &info`（VarRef）。带 `*` 出参的调用，测试必须真断言出参值 |

## E. Mac 坑（Swift / IOBluetooth / CoreAudio）

| 坑 | 正解 |
|---|---|
| `CFString("")` 不能构造 | `var name: CFString = "" as CFString`（残留一个 RawPointer 编译警告，CoreAudio 取设备名通行写法，无害） |
| **左键 toggle 建立在 `Watchdog.armed` 上** | 必须以**耳机实际连接状态**为准（`armed \|\| isConnected`）。看门狗被关后 armed 永远 false → 图标永远 💤、左键永远走"连接"分支、无法断开（2026-08-19 真机日志：用户连点 6 次全是 toggle → connected）。已修 |
| 右键菜单项"防止自动切走"是**开关**不是状态显示 | 用户会误点关掉看门狗。误关后症状=上一条 |
| 无 bundle id 的 SwiftPM CLI，UserDefaults domain | 是**进程名**（`AirPodsBuddyMac`），不是反写 DNS。查法：`defaults read AirPodsBuddyMac` |
