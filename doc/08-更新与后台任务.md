# 08 · 更新事务与后台任务

现状：v1.9.19 实现，故障注入与真实部署回滚已执行；公开 Release 尚未发布。
负责人：项目维护者与当前 Agent。
最后更新：2026-09-26。

## 修改原因
旧更新器直接接受网页 URL，同步下载，固定临时目录、未检查 tar 退出码、脚本追加且无版本健康回滚。旧反馈把 no-cors opaque 响应当送达，蓝牙与网络阻塞宿主。

## 更新事务
1. 宿主仅接受无参数 doupdate；后台重新请求指定 GitHub 仓库的 latest API。
2. 拒绝 draft、prerelease、不合法版本、其他域名/仓库、多个同名资产和缺失 SHA256 digest。没有可信摘要的历史发布包保留手动发布页，不盲目执行。
3. 下载到本任务唯一目录（90 秒网络超时、120 秒总截止），先核对摘要，再校验 ZIP 所有路径、总解压大小、symlink 和根 exe。只提取指定 exe。
4. 新文件复制到安装目录旁，核对复制哈希；原子 Replace 同时保留旧 exe，记录原始哈希，核对备份哈希。
5. 新进程收到唯一健康令牌。主 WebView 导航成功才写版本标记；继续存活三秒并复核版本后才提交成功回执。
6. 健康失败或异常恢复旧 exe，并按替换前哈希验收。备份损坏时明确 ROLLBACK_FAILED，不宣称恢复成功、不重启未知字节。
7. 新进程轮询更新回执，覆盖慢启动，避免仅启动 3.5 秒读取一次造成提示丢失。

这里使用 GitHub API 提供的资产摘要作为完整性来源，并未宣称 Authenticode 签名或私钥已配置。公开发版仍需用户明确同意。

## 后台任务
请求 JSON 与结果文件放独立任务目录，网页既不指定 worker 路径，也不传任意命令。
宿主持有实际进程句柄；退出/超时终止自己拥有的进程，不依赖可能复用的 PID；回调后关闭句柄并清理目录。
反馈全程只有一个在途事务，前端截止晚于 worker 的总截止；HTTP 2xx、进程退出码零均不替代业务 errcode=0。
降噪和蓝牙服务调用也走子进程。蓝牙 API 接受请求后，宿主继续异步核实真实链路与音频端点。

## 实测结论
- 真实部署时，第一包的导航规则误拦 WebView 内部 data URL，健康检查失败后旧 v1.9.17 被恢复并重新启动；这次失败被保留在日志中。
- 换成精确虚拟主机 URL 后，v1.9.19 导航、RPC 和三秒存活健康检查通过。
- 故障注入覆盖摘要不符、外部 URL、缺失 digest、ZIP traversal、非 PE、健康失败/异常、回滚内容核对、HTTP 业务拒绝、目标录音端点误判、finally 恢复设备。
- 测试未向真实反馈群发送试验数据，也未执行全局音频服务重启或自动蓝牙 radio reset。

## 最终复核追加
- 已退出worker优先读取结果，UI迟轮询不误报超时；合法业务结果不残留缺失回执错误。
- 健康检查异常由finally终止新子进程；失败回执写拒绝不阻断原始hash核对与旧版重启。
- 构建清单覆盖全部编译输入与工具hash，编译后和部署前复核；元数据复制错误不冒充应用回滚。
- 对应后台5项、健康异常3项回归通过。
