# 竞品对标与高级能力路线（2026-11-25）

目标：将最常用的 Windows 一键连接做稳、做快；把控制通道与音频通道分离，逐步实现 AirPods 高级能力。竞品 README 是作者的能力声明，不是本机真机验收。

## 2. 两条独立技术路径

- 普通连接：Windows Classic + 系统 KS。1.9.36 本机证明 AirPods 在链路 DOWN 时单独 HFP 过滤器连接可率先建立物理链路；然后 Windows 激活 A2DP，默认输出及实际听音验证通过，3 个默认输入角色保持不变。1.9.37/38 保留精确同目标、限时核实、一次有界回退，HFP 立体声迟到用连续观察窗口。无须内核驱动、管理员权限或降低系统保护。
- 控制通道：现有独立 1.10.0-beta.2 使用已安装兼容 AAP 控制接口。支持关闭/ANC/通透/自适应，新增自适应强度 0–100 协议和明确应用按钮；仅设备上报 Adaptive、选择适用型号且显式 H2 实验开关时开放。合法/新回读才显示状态一致；缺驱动不发送命令。
- 高音质麦克风：现有 HFP 不是高保真方案。实机无录音缓冲读取的 10 秒会话表明本机 HFP capture=1 声道、8000Hz；链路未掉，应用观察到 active 并推迟播放预检，结束后回到 idle。微软[Classic 音频](https://learn.microsoft.com/en-us/windows-hardware/drivers/bluetooth/bluetooth-classic-audio)和[通讯格式](https://learn.microsoft.com/windows/win32/coreaudio/communications-audio-format-capabilities)明确 Classic 同时使用耳机输入时不能提供 A2DP 立体声；LE Audio 也依赖兼容的电脑、适配器和耳机。不声称改 Windows 混音格式可改变无线编解码。高保真路线须独立输入通道/虚拟输入设备，先在可回退的隔离硬件验证。
- [Apple Adaptive Audio](https://support.apple.com/en-mide/guide/airpods/dev6d977ff21/26/web/26)确认能够选择环境声程度；[通透自定义](https://support.apple.com/en-ie/guide/airpods/dev966f5f818/web)还有放大、均衡、环境降噪等单独设置，不能把 Adaptive 滑杆假称所有模式的通透/降噪可调。实验包仅实现有明确公开协议事实的 Adaptive Level。

## 3. 用户选择与产品定位

所有者确认当前只有一个适配器，先交付安全实验室及验证，保留高级硬件路线，不自动安装、接管或更换驱动。普通主程序依然面向所有用户；高级实验室明确单独安装，不要求普通连接用户承担额外依赖。

核心生态位：轻量托盘一键连接、低权限解决日常场景；整窗开盒和可爱的角色品牌；不记录原始设备标识、不遥测、用户主动附脱敏证据；捞鱼软件中心分发、产品网页 latest 链接、Agent 排障入口。不是功能堆积；等待时间、可恢复性与实听证据优先。

## 4. 后续验收矩阵（不可用合成通过替代）

| 优先级 | 目标 | 验收条件 |
|---|---|---|
| P0 | Windows 冷连接 | 当前目标真实冷连接已通过一次；不同型号和硬件的五轮断开重连、真实听音、延迟及默认麦克风保持，全部记录结果。 |
| P1 | AAP 控制 | 在具备兼容、可信、签名控制通道的隔离环境，对关闭/ANC/通透/自适应各5次；真实设备回读、耳柄外部切换与实听，不自动写驱动。 |
| P1 | 自适应强度 | 已验证协议编解码、范围、陈旧回读、错误/超时、UI 门控；真实 0/50/100 切换与型号/固件边界仍待验证。 |
| P2 | 高音质耳机麦 | 专用备用适配器或独立 Windows 机，完整签名/许可/回滚检查；独立输入流与 A2DP 同时实际可听、通话中稳定、无原始录音留存、保留其他设备。 |
| P3 | 丰富状态与推广 | 状态来源明确的电量/入耳、最低限度资源消耗、公开说明兼容性；先完成正式发版门禁，再通过软件中心和入口页推广。 |
