## 发布核对清单

1. 核对本次版本的用户明确同意；选严格五轮档位或已知问题接受档位，保留真实失败与人工确认边界。
2. 按 [08-更新与后台任务.md](08-更新与后台任务.md) 生成最终 build、精确 ZIP 和预检回执；核对源码、构建、ZIP、安装 exe 的版本与哈希，并完成安装版真实行为验收。
3. 发布后核对 GitHub tag/Release target、资产 digest、CI 与公开文案；把证据写入 verification/ 和 [04-项目进度.md](04-项目进度.md)。
4. 同步独立网站产品页的版本、日期、两处下载链接、已知问题与 PAGE_VER；等待 Pages run 成功，从公网无缓存读回并核对 Release 资产 SHA256。未完成此步，不宣布发版闭环。

只改页面、文档或本地候选时按改动层级验证；不要误触发完整发布流程，也不要把未发布候选写成正式版。
