# 竞品对标与高级能力路线

现状：稳定；2026-11-26 补充复核 WPods 的已签名依赖路线 ｜ 负责人：项目维护者 ｜ 最后更新时间：2026-11-26

目标：把最常用的 Windows 一键连接做稳做快；把控制通道与音频通道分开看，逐步实现 AirPods 高级能力。竞品 README 是作者的能力声明，不是本机真机验收。本文每条事实带可信度标签：[官方文档]、[源码确认]、[作者声明]、[issue 用户报告]、[社区实测]、[推测]。

## 0. 结论速览

1. **降噪 / 通透 / 自适应在 Windows 上必须有内核驱动。** 微软蓝牙栈的用户态 Winsock 只接通了 RFCOMM，AAP 用的 L2CAP PSM 0x1001 只能从内核提交，和适配器品牌无关。在微软原生栈上直接提交 AAP 通道需要内核层能力；自研控制驱动不是唯一实现：WPods 声明复用已签名 USB/IP 驱动并代理适配器，无需 Test Mode。[官方文档] [源码确认]
2. **在 Classic 蓝牙的原生通话路径中，使用耳机麦不能保持立体声；但不等于必须自研并签名驱动。** WPods 声明通过已有签名依赖提供独立虚拟麦克风与 A2DP 播放；适用的 Windows 11/LE Audio 环境亦有原生立体声通话能力，AirPods 及本机适配性未验证。[源码确认]
3. **连接触发方面我们已经在最优路线上。** KS `ONESHOT_RECONNECT` 加 HFP 优先，与 ToothTray（BSD-2）和上游（MIT）的独立实现一致；WinRT / RFCOMM 兜底不值得做。[官方文档] [源码确认] [社区实测]
4. **收费竞品的招牌功能现在正被 Windows 卡着。** MagicAAP 官方驱动未签名、要开 Test Mode；社区签名版自 2026 年 4 月的安全更新起默认不被信任。这是 MagicAAP 自研驱动路线的限制，不能外推到所有竞品或其普通用户。[作者声明] [官方文档] [issue 用户报告]

## 2. 历史遗留问题一：降噪 / 通透 / 自适应

### 为什么不装驱动做不到

- 微软文档：Winsock 蓝牙套接字支持的是 `BTHPROTO_RFCOMM`；L2CAP 由内核 profile 驱动通过 BRB 使用。[官方文档]
- 实测现象：`AF_BTH + BTHPROTO_L2CAP` 的 `socket()` 成功，`connect()` 失败 `WSAENETDOWN (10050)`，Windows 11 24H2 上同样如此。[issue 用户报告]
- 没有任何项目发布过「换 Intel / Realtek 适配器就能用」的兼容性矩阵；换适配器或换厂商驱动不改变结果。[推测，基于检索无结果]
- WinRT 的 `Windows.Devices.Bluetooth.Rfcomm` 只有 RFCOMM；AAP 在 SDP 里是 L2CAP 服务，不能走 RFCOMM 承载。[官方文档] [issue 用户报告]
- 本机补测：32 位和 64 位进程创建蓝牙套接字（L2CAP 与 RFCOMM）都返回 `WSAEAFNOSUPPORT (10047)`，适配器在线；未向耳机发起任何请求。所以「用 WinSock 探测做诊断」的设想在这台机器上不成立，用户态没有可用的通道。[本机实测]

### MagicAAP 驱动的现状（2026-11）

- 架构：绑定在 BthEnum 为 AAP 服务创建的设备节点上的函数驱动，用 `GUID_BTHDDI_PROFILE_DRIVER_INTERFACE` 加 `BRB_L2CA_OPEN_CHANNEL`；同构开源实现 NTPodsAAP 与 SoundStage 的 INF 匹配 `BTHENUM\{74ec2172-0bad-4d01-8f77-997b2be0722a}`。[源码确认]
- 官方版未签名，必须开 Test Mode 并关 Secure Boot，作者自己警告只适合做好重装系统准备的高级用户。官网仍写着「如果你能给官方驱动签名请联系我」。[作者声明]
- 社区版用变通方法签名，可能被 Defender 或反作弊标记；2026 年 4 月安全更新后交叉签名驱动默认不受信任，官方称关闭该策略会降低设备安全性；2026-11-17 仍有装完重启后策略被重新启用的未解决 issue。[作者声明] [官方文档] [issue 用户报告]
- 第三方可以在用户已安装时复用其设备接口（AirPodsWindows 就这样做），但接口无文档、通道独占，且未找到作者对第三方复用的授权。[源码确认] [推测]

### 协议事实（可独立实现的部分）

| 项目 | 事实 | 可信度 |
|---|---|---|
| 位置 | L2CAP，PSM 0x1001 | [作者声明] |
| 设置模式 | `04 00 04 00 09 00 0D <01..04> 00 00 00`：01 关闭、02 降噪、03 通透、04 自适应；耳机回同样的包 | [作者声明] [源码确认] |

### 路线选择

| 路线 | 能得到什么 | 代价 | 结论 |
|---|---|---|---|
| 正规签名驱动（EV 证书 + 微软 attestation / WHQL） | 完整的降噪控制，且比竞品更安全可用 | 证书与认证成本、驱动开发与维护、需要公司主体 | 建议作为中期目标，这是收费竞品目前过不去的坎 |
| 复用用户已装的 MagicAAP | 用户自行承担风险后可用 | 接口无文档、可能与 MagicPods 抢通道 | 只做成默认关闭的实验性选项 |
| 接管适配器（WPods 路线） | 不需要自家驱动签名，作者声明可实现高级控制与立体声播放+耳机麦 | 需要管理员及已签名第三方驱动，改变整机蓝牙适配器路径，兼容/回滚/许可需验证 | 主程序不采用；先研究独立实验方案，不部署或接管本机 |
| 无驱动的 BLE 广播 | 电量、入耳检测、弹窗 | 较新固件可能加密广播 | 值得做，见路线图 P2 |
| 诚实降级 | 控件置灰并说明原因 | 无 | 当前默认 |

### 正规签名的门槛与成本（2026-11-26 查证）

- **注册微软硬件开发者计划**：必须有 EV 代码签名证书（注册时上传；提交驱动时还要先用它签 CAB）、一个组织的 Microsoft Entra ID 全局管理员账号（可免费创建）、有权签协议的公司联系人、公司信息或 DUNS 编号（可选）。微软会发邮件问卷了解业务，签四份协议。官方页面没有提收费，也没有写审核时长。[官方文档]
- **证明签名**：不需要 HLK 测试。文档现在把它归在「测试场景」下，明确写「不能发布到 Windows Update 面向零售用户」；同一页的兼容表写明 Windows 10 及以上可以加载。自己分发、不走 Windows Update 时按理解为够用，但文档没有明说可以用于商业零售分发，办证前要向微软或代理商确认。[官方文档] [推测]
- 证明签名不检查内存完整性（HVCI）兼容性。Win11 新装默认开启它，驱动必须自己做到兼容，否则加载不了。[官方文档]
- **费用**（机构官网标价，成交前需再确认）：沃通 EV 代码签名标准版 ¥4,288/年、Pro ¥6,888/年，含硬件 Key，1–3 个工作日签发；SSL.com 一年期 $349/年，多年期更低，云签名另订。EV 只发给注册的公司或组织，个人办不了。
- 已签好的驱动由微软重新签名，不依赖自家 EV 证书是否过期；只有提交新版时才需要有效证书。[推测，基于文档描述]
- **MagicPods 官方帮助页原文**：安装前创建还原点、备份 BitLocker 恢复密钥（安装和卸载各要输两次）、关闭 Secure Boot、运行 `bcdedit /set testsigning ON`、确认安装未签名驱动；页面顶部警告只建议做好重装系统准备的高级用户安装。社区版要关闭 Defender 实时保护、导入根证书、给驱动目录加排除项；装了 2026 年 4 月更新的系统必须禁用 Windows 驱动策略，并在使用期间保持禁用。[作者声明]
- **所有者决定（2026-11-26）：这条路暂缓，先不做驱动。** 主程序保持免驱动、零管理员，对公众如实说明卡点。

## 3. 历史遗留问题二：用耳机麦后音质差、容易掉

### 原因

- 微软文档：Classic 蓝牙使用耳机麦克风时走 HFP，采集与播放都是单声道，A2DP 与 HFP 不能同时成立。[官方文档]
- 本机实测 HFP 采集是 1 声道 8000Hz，属于窄带回退；能否协商到 16kHz 的 mSBC 取决于适配器、驱动和耳机三方，没有强制开关。[官方文档]
- 每次开关麦都会触发 A2DP 与 HFP 互切，多应用争用时反复切换，期间有间断并可能掉线。[官方文档] [推测]
- AAP 麦克风流与 HFP 同时进行会让 AirPods 掉链路。[源码确认]

### 竞品怎么绕

- NTPods、WPods、LibrePods 的 PR 用的是同一组报文：发 19 字节 `START_AUDIO`，收 0x58 上行包，用 AAC-ELD 解码后写入虚拟麦克风。NTPods 用两个测试签名驱动；WPods 靠接管适配器加虚拟 USB 麦。[源码确认]
- 即使做到，用麦时播放仍可能是单声道（NTPods 作者自述），只有 WPods 声称 H2 型号能保持立体声，且项目很新、稳定性问题未关闭。[作者声明] [issue 用户报告]
- SoundStage 与 MagicPods 都没有解决，官方建议都是「输出走 Stereo，另用一个麦」。[作者声明]

### Mac 为什么听起来正常

- Apple 自己的文档承认：蓝牙切到用麦的模式后音频质量会下降，直到不再使用麦克风。[官方文档]
- 2024 年固件为 AirPods Pro 2 带来通话语音隔离，提到 16-bit / 48kHz 音频；2025 年固件为 H2 机型带来录音棚级录音，并称通话语音更自然。处理在耳机与 Apple 设备之间完成。[官方文档]
- 所以 Mac 的优势来自 Apple 私有的宽带通话通道和语音隔离，加上 macOS 常直接用电脑自带麦；这不等于「用耳机麦还保持 AAC 立体声」，Windows 上无法等价复制。[社区实测] [推测]

### 零驱动能做的（第①层，建议现在就做）

- 引导通话软件使用电脑麦克风，耳机保持 A2DP 立体声；这同时消除了互切和大部分掉线。
- 提供「禁用此耳机的免提」开关（默认关）：调用公开 API `BluetoothSetServiceState` 对单个已配对设备停用 Hands-Free，耳机麦不可用但播放始终是立体声，可逆。MagicPods 与 WPods 都有这个开关。[官方文档] [源码确认]
- 如实披露：耳机麦在这台机器上是 8kHz 电话音质，改不了；不能替别的应用选麦，只能引导或经同意改默认设备。

第②层（虚拟麦克风驱动）与第③层（接管适配器）都和「不装内核驱动」冲突，暂不做。

## 4. 连接触发：证据排序

| 排序 | 方式 | 证据 |
|---|---|---|
| 1 | 对 HFP 端点过滤器发 KS，再等 A2DP 激活 | 本机 4 次成功；上游与 btcom 都是 HFP 在前 [源码确认] [社区实测] |
| 2 | 对容器内所有过滤器发 KS，HFP → A2DP | ToothTray 的做法，多人确认可用 [源码确认] |
| 3 | `BluetoothSetServiceState` | 会安装对应驱动；有「已连接但没声音」的报告 [官方文档] [社区实测] |
| 4 | WinSock SDP 查询或 `connect()` 探测 | 没有能带出音频端点的证据；本机连套接字都创建不了，诊断价值也用不上 |
| 5 | WinRT 套接字 | 只到「已连接」无音频，释放即断；32feet 维护者明确不推荐 [社区实测] |
| 6 | PnP 禁用再启用 | 需要管理员，等于重装设备栈 |

要点：

- `KSPROPERTY_ONESHOT_RECONNECT` 成功只表示驱动尝试过，不代表连上；官方建议用插孔描述核实端点。本项目发的是 `KSPROPERTY_TYPE_GET`，与文档和 ToothTray 一致。[官方文档] [源码确认]
- 没有任何资料解释「A2DP 卡在已配对而 HFP 先拉起链路」的栈内原因，只有间接证据。[推测]
- Windows 11 把端点合并成一个，枚举必须包含采集方向，否则会漏掉 HFP 过滤器、断开时麦克风还连着。[作者声明] [issue 用户报告]
- 本机的 BTHUSB Event ID 3 是适配器 HCI 命令超时警告，没有官方根因文档；它同时拖慢系统设置里的连接。[issue 用户报告]

## 5. 连不上时的自救清单（只列有来源的）

1. 耳机关机几秒再开机，确认在范围内。[官方文档]
2. 关闭电脑蓝牙，等 10 秒再打开。[官方文档]
3. 把适配器移离 USB 3.0 设备，换 USB 2.0 口或 USB 2.0 hub。[官方文档] [社区实测]
4. 笔记本自带蓝牙又插了适配器时，只保留一个。[社区实测]
5. 设备管理器里取消适配器的「允许计算机关闭此设备以节约电源」。[官方文档]
6. 重启 Bluetooth Support Service。[官方文档]
7. 连上但没声音：确认输出选的是耳机的 Stereo 而不是 Hands-Free，格式设为 2 声道 16 位 48000 Hz。[官方文档]
8. 同一时段系统日志里有 BTHUSB 事件 3 / 5 / 17 时，提示这是适配器或 USB 链路问题。[issue 用户报告]

## 6. 生态位

- 做最稳、最轻的一键连接：不要管理员、不装驱动、HFP 优先。
- 把零驱动能做的做满：通话保音质引导、免提开关、BLE 电量与入耳。
- 对国内用户友好：更新与下载走可用线路（直连 GitHub 在国内基本不可用）。
- 隐私与诚实：不采集原始设备标识，不把失败写成通过。
- 中期护城河：正规签名的 AAP 驱动。

### 2026-11-26 · 标准系统电量属性实机评估

微软定义 [System.Devices.BatteryLife](https://learn.microsoft.com/en-us/windows/win32/properties/props-system-devices-batterylife) 为 Byte 百分比，属性键可由 [Get-PnpDeviceProperty](https://learn.microsoft.com/en-us/powershell/module/pnpdevice/get-pnpdeviceproperty) 按 GUID/PID 查询；[设备容器](https://learn.microsoft.com/en-us/windows/apps/develop/devices-sensors/device-information-properties) 可用已知目标的 ContainerId 定点查询 DeviceInformation 属性。注意微软 [BluetoothCacheMode](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.bluetoothcachemode) 明确某些 GATT Cached API 在缓存缺失时会访问远端，不能将其称为完全被动的系统元数据读取。

独立工具 `scripts/probe-os-battery.ps1` 仅从显式指定的、已有确切配对节点和容器读取该属性，不初始化 Bluetooth LE/GATT、扫描或改动设备；不读取其他设备属性，不持久化或发送标识。只接受 Byte 0–100；双来源冲突、无值或异常均不提供百分比。即使读到有效值，也仅是整体设备百分比，未验证实时性与左右耳、盒子归属。

实际在已知本机配对目标上，节点唯一，PnP 属性类型 Empty，容器查询成功但属性缺失；独立工具输出 status=absent、percent=null。此一次观测不能证明所有固件或连接状态都没有系统电量。新增 8 项无硬件夹具测试，整套 32/647 通过。工具未入主程序构建，未加后台轮询或展示电量；下一步需选择指定设备，在可控状态下独立验证被动广播归属与准确性，不把缺失值当零电量。


### 2026-11-26 · 重新核对：普通用户能否使用高音质耳机麦

- [WPods 官方 README](https://github.com/FPNDev/wpods)：声明当前版本可在 Secure Boot 开启的普通 Windows 11 x64 环境安装；需要管理员，借助 WinUSB 和 usbip-win2 提供虚拟蓝牙适配器及 USB 麦克风，非传统 HFP 麦。作者报告实测 AirPods Pro 2/3 和 Intel AX211，其他适配器未完成作者测试；不等同于本机 Win10/Realtek 实证。
- [usbip-win2 上游](https://github.com/vadimgrn/usbip-win2) 与 [官方 Releases](https://github.com/vadimgrn/usbip-win2/releases)：存在微软签名的 x64 驱动资产；上游说明包含 WHLK/attestation 范围和版本区别，不能把任何架构或版本均视为商业分发已获许可。WPods 不需要自己取得 EV 证书的原因是使用已有签名驱动，不代表完全免驱动。
- [MagicPods 官方帮助](https://help.magicpods.app/issue-mic-low-quality/)：原生 HFP 音质问题没有软件设置解法，推荐外置/电脑麦。不要将其普通版的连接能力误判为耳机实体麦与立体声同时工作。
- [微软通信音频格式](https://learn.microsoft.com/en-us/windows/win32/coreaudio/communications-audio-format-capabilities)：Classic HFP 采集与输出均为单声道，可协商 8 或 16kHz；部分 Windows 11 LE Audio 设备支持使用麦克风时的立体声播放。必须核对 PC、驱动和目标耳机支持，不能由操作系统版本单独推断。

产品方向（2026-11-26 所有者确认重点攻关）：将高音质耳麦作为独立高级路线推进，不再以“必须自己签名”作为唯一停止理由。分阶段任务与验收门槛统一见 [roadmap](roadmap.md)。首选调查兼容的原生 LE Audio 或可复用已签名依赖的隔离方案；不在生产主程序接管用户适配器、不降低安全策略、不直接合并 GPL 源码。待证据：目标环境真实耳机麦、播放双声道及采样格式、实际听音/通话、配对与其他设备不受损、退出恢复和再安装，随后决定是否独立发行。未安装竞品或任何驱动。


### 2026-11-26 · 高音质耳麦第一阶段：本机可行性与实际依赖核验

独立实验测量工具见 `tests/duplex_call_observation.py`：由测试人员手动开始通话和播放，工具仅查询精确端点活动情况和共享混音格式；要求前后两次播放与录音会话均活跃，不能证明物理声源或听音。真实本机无活动会话时，输出 2ch/44100Hz、输入 1ch/8000Hz，返回 insufficient_observation；不发蓝牙请求、不开音频流，不记录实际声音或设备标识。下一阶段在可控 Win11 设备/备用适配器上进行实测，本机不能作为原生 LE Audio 正向验收台。
