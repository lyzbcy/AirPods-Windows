# 15 · 环境与协作踩坑

现状：持续追加 ｜ 负责人：项目维护者 ｜ 最后更新时间：2026-11-25

> 读这份文档的时机：改目录、清理文件、写 PowerShell 辅助脚本、或者怀疑有别的会话也在改这个仓库之前。软件本身的缺陷和环境陷阱在 [05](05-已知问题与踩坑记录.md)。

## 1. 目录改不了名：子目录上有打开的句柄

- **现象**：`Rename-Item` 报「对路径的访问被拒绝」，错误码 5，POSIX 语义改名也一样被拒；权限本身没问题。
- **原因**（本机实验确认）：Windows 10 上，只要目录树的任何一个子孙目录上有打开的句柄，祖先目录就不能改名。哪怕这个句柄允许共享删除、只是空闲的监听也不行。监听目录自己反而可以改名。
- **这次的占用者**：VS Code 的文件监视进程占着项目的 `.git` 目录。编辑器开着这个仓库时必然出现。
- **查法**：按对象类型枚举系统句柄表（x64 缓冲区前 16 字节是头），复制句柄后用 `FileNormalizedNameInfo` 取路径；对同步挂起的句柄取名会阻塞，必须放工作线程并带超时。工作目录在树里的进程读 PEB 的 `CurrentDirectory` 即可。
- **解法**：把 `.git` 用 `Move-Item` 挪到同级临时目录 → 改项目目录名 → 把 `.git` 挪回去；任何一步失败都在 `finally` 里复原。不需要关闭任何进程。
- **教训**：`Rename-Item -NewName` 只能在同一目录内改名，要跨目录必须用 `Move-Item -Destination`。这类脚本先在 `%TEMP%` 的一次性目录里，用一个持有句柄的辅助进程演练通过，再碰真仓库。

## 2. 旧构建和回退副本会无限堆积

每次构建生成一个 `dist/build-<guid>`，每次部署和自动更新留一个 `AirPodsBuddy.exe.backup-<guid>`，以前都不清理，一天就能堆到几百 MB。现在构建只留最新两个，健康替换后只留最近几份回退，见 [08](08-更新与后台任务.md)。

## 3. PowerShell 5.1 吃中文脚本的三种乱码

- 通过标准输入传脚本正文（`powershell -Command -` 加 here-string）会按 GBK 解析 UTF-8，中文路径全错。路径要当参数传，或者脚本保持纯 ASCII。
- `.ps1` 文件含中文且没有 UTF-8 BOM 时按 ANSI 读，字符串字面量会坏。
- 原生命令的 `-Command '...'` 里出现「反斜杠紧跟双引号」会被参数转义吃掉反斜杠，`\\?\` 前缀就这么坏过。

## 4. Git Bash 里输出突然全是乱码

整段输出先按 UTF-8 解码，只要有一个非法字节就整段回落到 GBK。`cut -c` 截断多字节字符、PowerShell 的 GBK 输出和 bash 的 UTF-8 输出混在同一条命令里，都会触发。用 `iconv -f GBK -t UTF-8` 单独转换，不要用 `cut` 截中文。

## 5. 链式命令不要用管道掩盖退出码

`git branch --track … | tail -2 && git symbolic-ref HEAD …`：第一条失败被 `tail` 吃掉，后面照常执行，结果 HEAD 指向了一个不存在的分支。改仓库状态的命令链里不要插管道，或者用 `set -e` / `PIPESTATUS`。

## 6. 国内直连 GitHub 基本不可用

2.6MB 的正式包直连 8 分钟只收到 4KB；镜像几秒完成。取回后必须用 GitHub 公布的 SHA-256 摘要校验再用。更新器目前的直连线路因此需要改，见 [08](08-更新与后台任务.md)。

## 7. 同一工作树可能有多个 Agent 会话

2026-11-25 实际发生：一个会话在搬文档，另一个「接管复核」会话几分钟后顺着新结构改链接、改 `AGENTS.md`。动手前看 `git status` 和文件最近修改时间，改别人也可能在改的文件前重新读一遍，不要用缓存里的旧内容整文件覆盖。

## 8. 安全软件可能拦脚本

本机安全软件会间歇性拦截写文件和删除脚本。批量删除之前先核对 Git 状态，删完再核对一次；被拦就按约定写清理报告，不要绕过。

## 9. 沙箱里启动的应用带受限令牌

从沙箱 shell 直接启动应用可能行为异常。需要用户侧启动时走 `explorer.exe <path>`，或者让用户自己点。

## 10. AHK 测试脚本引用了没定义的函数不会失败，而是挂起

把生产函数提取进测试脚本时，它内部调用的每个函数都必须有桩，否则加载时弹出错误框等用户点确认，看起来就是超时且没有任何输出。`/ErrorStdOut` 拦不住这种框。排查办法是用带 5 秒超时的小驱动对脚本做二分，不要反复盲跑。测试脚本顶部加 `OnError((*) => ExitApp(1), -1)`，运行错误才不会弹框。

## 11. AHK v2 对象字面量里的箭头函数属性要接收 this

`{f: () => 1}` 再用 `obj.f()` 调用会报参数过多。写成 `{f: (*) => 1}` 或 `{f: (this) => ...}`。给 WebView2 的参数对象做假对象时容易踩到。

## 12. 提取函数做测试时要改名

测试脚本里如果已经为同一个函数放了桩，再追加提取出来的真函数会重名。把真函数改名（例如 `RealOnConnectSuccess`）后单独调用，桩保持原样给其他代码路径用。
