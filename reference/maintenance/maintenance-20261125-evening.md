## 3. 目录改名

- 现象：`Rename-Item` 报错误码 5，POSIX 语义改名也被拒；权限本身允许修改。
- 定位过程：写只读句柄扫描（系统句柄表前 16 字节是头；对同步挂起的句柄取名会阻塞，需要放工作线程并带超时）。全树只有一个可见句柄：VS Code 的文件监视进程占着项目的 `.git` 目录。
- 验证规则：在临时目录用辅助进程持有一个「共享删除的空闲目录句柄」，确认子目录上有句柄时父目录不能改名，而句柄所在的目录自己可以改名。
- 解法：把 `.git` 用 `Move-Item` 挪到同级临时目录，改项目目录名，再挪回去；先在临时目录演练通过再执行。结果：目录改名为产品名，`.git` 完整归位，没有关闭任何进程。
- 一次失误：第一版脚本误用 `Rename-Item -NewName`，它只能在同一目录内改名，导致 `.git` 被临时改名为 `.git-aside-…` 且复原步骤找错位置。立即手工改回，`git` 状态、暂存区和 HEAD 均正常。教训已记入 [15](../../docs/15-环境与协作踩坑.md)。
- 同步更新：logo 来源登记里的图标路径、AGENTS.md 中的仓库路径。

## 6. 调研

三份只读调研的结论、可信度标签和来源汇总在 [14 · 竞品对标与高级能力路线](../../docs/14-竞品对标与高级能力路线.md)。与本机直接相关的三条：

- 降噪 / 通透 / 自适应在 Windows 上必须有内核驱动；微软栈的用户态打不开 AAP 的 L2CAP 通道，与适配器品牌无关。MagicAAP 官方驱动未签名，社区签名版自 2026 年 4 月起默认不被信任。
- 用耳机麦保持高音质同样需要内核驱动；零驱动只能引导用户用电脑麦克风。
- 本项目的 KS 请求用的是 `KSPROPERTY_TYPE_GET`，与微软文档和 ToothTray 一致；HFP 在前有独立实现佐证；不加 WinRT / RFCOMM 兜底。
